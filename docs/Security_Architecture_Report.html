Data Flow & Security Architecture

Project: Guardian's Embrace Volunteer Portal Status: Release Candidate 1.0 Date: March 2026

1. Executive Summary

The Guardian's Embrace Volunteer Portal is a decoupled web application designed to facilitate volunteer contributions while maintaining high standards for data integrity and organizational security. This document outlines the technical architecture, data flow paths, and security controls implemented to protect volunteer identity and organizational assets.

2. High-Level Architecture

The system utilizes a modern stack optimized for security and scalability:

  • Frontend: React 18 / TypeScript / Vite.
  • Backend: FastAPI (Python 3.12) REST API.
  • Database: MongoDB (NoSQL) for metadata and state.
  • Storage: Google Drive API (Shared Drive via Service Account).
  • Identity: Google OAuth 2.0 (OIDC).

3. Data Flow Analysis

3.1 Authentication Strategy (OIDC)

The portal employs a passwordless architecture. We do not store or process raw credentials.

  1. User initiates login via Google SSO on the frontend.
  2. Google returns an id_token / access_token to the client.
  3. Frontend transmits the token to the backend /auth/google endpoint.
  4. Backend verifies the token integrity directly with Google API.
  5. Upon successful validation, backend issues a short-lived, signed JWT (JSON Web Token).

3.2 Secure File Ingestion

Volunteer submissions are handled via a proxied streaming mechanism:

Flow Stage Action Security Control
Ingress Volunteer uploads work snapshot (max 25MB) MIME type checking & size limits
Processing Backend validates user Role and Project scope RBAC (Role Based Access Control)
Storage File streamed to Google Shared Drive via Service Account Encryption at rest (AES-256)
Cleanup No permanent local file storage on the API server Disk sanitization policy

5. Identity & Access Management (IAM)

5.1 Principle of Least Privilege

The Google Service Account is configured as a Content Manager on the specific Shared Drive only. It has no access to the wider organization workspace (Email, Calendar, etc.).

5.2 Internal RBAC

  • Volunteer: Limited to own data and submissions.
  • Team Lead: Management access for assigned projects.
  • Admin: System-wide configuration and user management.

8. Risk Mitigation & Resilience

The application features a Circuit Breaker for cloud storage; if Google Drive is unreachable, data is encrypted and cached locally until the service recovers, ensuring no data loss.
